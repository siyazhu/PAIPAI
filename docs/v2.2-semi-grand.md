# PAIPAI v2.2: per-element fixed-count / chemical-potential controls

## Model

PAIPAI v2.2 adds an **optional** mixed canonical/semi-grand-canonical
sampling model. The original behavior remains the default: all elements
have fixed total numbers and the original swap/hop moves still work.

For each chemical species present in `struc.in` (including species with an
initial count of zero), choose one of:

- `--species Ti=fixed`: its *global* atom number is fixed, but its atoms may
  move to any substitutional site through ordinary swaps. This is **not**
  a frozen sublattice constraint.
- `--species Si=mu:-4.0`: the atom number can change, with a constant
  chemical potential of -4.0 eV per Si atom.

Unspecified species default to `fixed`. Ti, Al, and Si are free to occupy
**any substitutional lattice site**, including Ti-on-Al and Al-on-Ti
antisites. C (when declared as an interstitial species) can occupy or leave
the pre-enumerated interstitial sites.

For fixed substitutional site count `M=N_Ti+N_Al+N_Si`, all three populations
cannot vary independently. A single-site Ti→Si transmutation is legal only
if **both** Ti and Si are configured as `mu`, otherwise that move would
violate the fixed-count constraint. Ordinary pair swaps are always allowed
and preserve every element count. Interstitial insertion/deletion changes
the total physical atom count but not the number of allowed interstitial
positions.

## Thermodynamic objective

The raw relaxed MLIP energy is still saved as `energy`. For MC ranking and
acceptance use the reduced potential

```text
Omega = E - sum_{i configured as mu} mu_i * N_i
```

The contributions of fixed-count species are constants and can be
discarded. Because the substitutional site count is fixed, shifting all
substitutional chemical potentials by the same constant does not change
any equilibrium distribution when all relevant substitutional species are
open.

The v2.2 single-site transmutation proposals select uniformly among
mutable sites and uniformly among alternative open elements; their
reverse-proposal probabilities are equal. Existing local-hop moves
retain their Hastings correction.

Note: `finiteT` samples a **relaxed-energy surrogate** and does not include
vibrational/configurational basin free energies beyond explicit lattice
occupancies, nor does it guarantee thermodynamic accuracy for an
unvalidated MLIP. An approximate local relaxation can also make the
effective energy depend on the starting structure. Verify reproducibility
and convergence before interpreting finite-temperature concentrations.

## Example: Ti–Al–Si–C

Start from a fully optimized gamma-TiAl or alpha2-Ti3Al supercell.
Make a PAIPAI `struc.in` with *substitutional* species `Ti Al Si`
(including `Si` with count 0 when initially absent) and *interstitial*
species `C` with its initial count and a complete list of candidate
interstitial sites. Do not put substitutional Si in the interstitial list.

```sh
# First validate names and options without launching workers:
mc_paipai struc.in --dry-run \
  --species Ti=mu:-5.5 --species Al=mu:-3.7 \
  --species Si=mu:-4.8 --species C=mu:-7.2

# Actual run via the paipai wrapper:
paipai -i struc.in --mode finiteT --temp 700 --slow 1 \
  --p-swap-metal 20 --p-swap-inter 10 \
  --p-exch-metal 50 --p-exch-inter 20 \
  --species Ti=mu:-5.5 --species Al=mu:-3.7 \
  --species Si=mu:-4.8 --species C=mu:-7.2
```

**All chemical potentials above are made-up examples, not values for
Ti–Al–Si–C.** Obtain physically allowed reservoirs from phase equilibria,
check competing phases (e.g. carbides/silicides), and ensure the energy
zero and MLIP energy convention are consistent.

To fix the number of Ti but allow Al and Si to exchange with reservoirs:

```sh
paipai -i struc.in --mode finiteT --temp 700 \
  --p-swap-metal 30 --p-swap-inter 10 \
  --p-exch-metal 40 --p-exch-inter 20 \
  --species Ti=fixed --species Al=mu:-3.7 \
  --species Si=mu:-4.8 --species C=mu:-7.2
```

To keep Si fixed but allow Ti/Al to change, use
`Si=fixed`, `Ti=mu:...`, and `Al=mu:...`.
All element counts remain fixed if no `mu` policies are supplied.

## Sublattice / antisite statistics

The initial ordered geometry defines immutable origin-site labels:
Ti-origin and Al-origin substitutional sublattices (not atomic identities).
v2.2 saves a fifth integer in each **metal site** row in `SAVE`:

```text
x y z current_occupation_type original_sublattice_type
```

Old four-column SAVE files remain readable, but their original
sublattice labels cannot be reconstructed after prior antisite disorder.
For reliable antisite statistics, start a new v2.2 run from the ordered
reference structure or manually provide original-site labels.

Every accepted/rejected proposal logs raw energies, generalized energies,
current proposed element numbers, and the Ti/Al-origin sublattice
occupancy matrix (e.g., `Ti_site{Ti:...,Al:...,Si:...}`).

## Search versus finiteT

- `search` can optimize Omega at a chosen set of chemical potentials.
  Fast worker pool ranking uses `E_screen - sum(mu N)` instead of raw E.
  Its screening/selection trajectory must **not** be interpreted as
  an equilibrium MC chain.
- `finiteT` uses the sequential slow-worker path and a
  Metropolis/Hastings acceptance test on Omega. It is intended for
  approximate finite-temperature configurational statistics, subject to
  MLIP and relaxation checks.

Run `cmake -S . -B build && cmake --build build -j && ctest --test-dir build`
to build and execute the C++ policy regression tests.

## Current limitations

- A substitutional lattice site is always occupied by exactly one of
  its listed species. **True substitutional vacancies** are not yet
  modeled.
- The enumeration of interstitial sites is supplied externally, as in
  prior PAIPAI versions.
- All species can access all substitutional positions. Sublattice-specific
  forbidden-element constraints are not yet implemented.
- Atom/site labels and absolute chemical potentials must be supplied
  consistently, especially on resumed runs.
